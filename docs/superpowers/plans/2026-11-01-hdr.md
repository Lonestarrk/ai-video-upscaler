# HDR Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export the upscaled video as HDR10+ (with HDR10 fallback), HDR10 or HLG by converting the finished SDR frames to stored 16-bit HDR frames, measuring them, and encoding with correct metadata — without new AI calls.

**Architecture:** A new `hdr` module in `upscaler-core` adds a stage after upscaling: FFmpeg `libplacebo` (Vulkan) inverse-tone-maps `out/` frames into `<job>/hdr/` 16-bit PQ/HLG PNGs (cached by a key file), Rust measures them (MaxCLL/MaxFALL, per-frame stats), an `hdr10plus` module writes the per-scene JSON, and the encoder takes the HDR frames with x265 10-bit HDR parameters. The frame browser shows SDR/HDR status and can reject HDR frames.

**Tech Stack:** Rust 2021, egui 0.37, FFmpeg 7 (gyan full build: libplacebo + libx265), Vulkan; `image` crate 16-bit PNG.

**Spec:** `docs/superpowers/specs/2026-11-01-hdr-design.md` (Swedish). Research: `docs/research/2026-11-01-hdr.md`.

**Depends on:** the `surround-audio` branch (it changes the export flow: video is encoded to an intermediate `<job>/video.mkv` and muxed with audio; HDR plugs into that video encode). Execute after that plan is merged, on a new branch `hdr` from it.

## Global Constraints

- CLAUDE.md conventions: English code/comments/commits; UI text via `tr("sv","en")`; `cargo fmt --all` + `cargo test --workspace` before each commit; ffmpeg tests in `crates/upscaler-core/tests/`, skipping when ffmpeg is missing.
- `out/` frames are never modified. HDR frames live only in `<job>/hdr/`.
- HDR modes: `Off`, `Hdr10Plus`, `Hdr10`, `Hlg`. When the user turns HDR on, the UI selects `Hdr10Plus`. Peak choices 600 / 1000 (default) / 1500 nits. SDR reference white = 203 nits.
- HDR frames: 16-bit RGB PNG (`gbrp16`/`rgb48` from FFmpeg), BT.2020 primaries, PQ (`smpte2084`) for Hdr10/Hdr10Plus, HLG (`arib-std-b67`) for Hlg; max lossless compression.
- libplacebo needs `-init_hw_device vulkan`. Verified shape on this machine: `-init_hw_device vulkan ... -vf "format=yuv420p,libplacebo=inverse_tonemapping=true:colorspace=bt2020nc:color_primaries=bt2020:color_trc=smpte2084:format=yuv420p10le"`.
- Encoding: libx265, `yuv420p10le`, `-color_primaries bt2020 -color_trc smpte2084|arib-std-b67 -colorspace bt2020nc`; x265-params `hdr10=1:hdr10-opt=1:repeat-headers=1:colorprim=bt2020:transfer=smpte2084:colormatrix=bt2020nc:master-display=G(13250,34500)B(7500,3000)R(34000,16000)WP(15635,16450)L(<peak*10000>,1):max-cll=<MaxCLL>,<MaxFALL>` (+ `dhdr10-info=<json>` for Hdr10Plus). HLG: no master-display/max-cll. H.264 is never used with HDR.
- MaxCLL/MaxFALL are measured from the HDR frames, never fixed values.
- "Delete HDR frames after a successful export" defaults to on.
- Vulkan must be checked before any frame work when HDR is on.

## Review Focus

1. Vulkan unavailable (RDP, VM, old driver) → export fails at once with a clear message, before Upscaling → Task 3 test.
2. HDR with "every 2nd/3rd + interpolation" and anamorphic DVD output → fps exact, SAR kept, still PQ/BT.2020 → Task 4 test.
3. Very dark scenes (space): MaxFALL > 0 and sane; no NaN; HDR10+ scene stats do not jump at a cut inside a scene → Tasks 2 and 5 tests.
4. Changing only peak/mode → no AI calls, `hdr/` re-converted, `out/` untouched → Task 3 test.
5. A single-scene short range → valid HDR10+ JSON that `hdr10plus_tool` accepts → Task 5 test.

### Task 3: HDR conversion stage with cache and Vulkan check

**Files:** Create `crates/upscaler-core/src/hdr/convert.rs`; modify `crates/upscaler-core/src/job.rs` (new `Stage::Hdr` after Upscaling; run before encode when `hdr_mode != Off`).
**Produces:** `fn vulkan_available(tools: &Tools) -> bool` (1-frame libplacebo probe on a generated 16×16 input; env `UPSCALER_NO_VULKAN=1` forces false for tests); `fn convert(tools, out_dir: &Path, hdr_dir: &Path, total: u64, mode: HdrMode, peak_nits: u32, cancel, progress: impl FnMut(u64)) -> Result<()>` — one FFmpeg run over the PNG sequence: `-init_hw_device vulkan -framerate 1 -start_number 1 -i out/%06d.png -vf "format=yuv420p,libplacebo=inverse_tonemapping=true:colorspace=bt2020nc:color_primaries=bt2020:color_trc=<smpte2084|arib-std-b67>:format=gbrp16le" -start_number 1 hdr/%06d.png` (exact libplacebo peak/white parameters chosen after a visual check on the `tester\HDR` frames; record them as constants with a comment); `hdr/settings.txt` holds `mode, peak, HDR_VERSION=1`; when it matches and all frames exist, nothing is converted; otherwise the folder is cleared and redone. `fn hdr_status(job_dir, n) -> HdrStatus { Missing, Converting, Ready }` for the browser. Export checks `vulkan_available` before Extracting when HDR is on and fails with "Vulkan (needed for HDR) is not available on this computer" (English in core; GUI translates by matching a constant).
- [ ] Failing tests (ffmpeg, skip without Vulkan where noted): `converts_to_16bit_pq` (3 SDR frames → 3 PNGs, 16-bit, a white SDR pixel maps to ≥ 203 nits PQ and a mid-gray stays within ±25 % of its SDR luminance ×2.03); `cached_when_settings_match` (second call converts nothing — check file mtimes); `changed_peak_reconverts`; `no_vulkan_fails_fast` (env set → export `Failed` before any `Extracting` progress). Implement; pass; commit.
